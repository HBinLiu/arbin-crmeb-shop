# SaaS 多租户改造方案

> 文档依据：项目内讨论结论整理（截至 2026-09-04）  
> 仓库：`arbin-crmeb-shop`（CRMEB 单店版演进）  
> 状态：**需求与边界已定稿，待分阶段实现**

---

## 1. 目标与边界

### 1.1 要达成什么

| 目标 | 说明 |
|------|------|
| SaaS 多租户商城 | 一套代码、多客户（租户）隔离经营 |
| 数据模型 | **单库 + `tenant_id`** |
| 独立小程序 | 每租户独立小程序 / 公众号（开放平台代授权） |
| 资质按租户 | 支付子商户、短信等通道按租户配置 |
| C 端完整隔离 | 用户 / 商品 / 订单等互不可见 |
| 平台独立运营 | 同域二级路径 `/platform` 的平台端登录与管理 |
| 支付服务商 | 服务商代收 + 可选分账（已有单店分账能力可演进） |

### 1.2 明确不做 / 外置

| 项 | 说明 |
|----|------|
| CRMEB 内小程序上传 / 审核 / 发布 | 由 **wxcomponent**（微信云托管第三方平台模版二开）完成 |
| CRMEB 自建完整开放平台授权中心 | 不接 `component_verify_ticket`、不存 `refresh_token` |
| 完善 `crmeb/.../Open3rd/` 半成品当授权中心 | **搁置 / 废弃双轨** |
| 事业部 / 代理商模块 | **砍掉** |
| 授权回调自动带 `tenant_id` 绑定 | 不采用；采用 **方案 A：人工绑定** |

### 1.3 外部系统：wxcomponent

- 源码位置：仓库根目录 `wxcomponent/`（自 `wxcloudrun-wxcomponent` 二开复制）
- 上游参考：[WeixinCloud/wxcloudrun-wxcomponent](https://github.com/WeixinCloud/wxcloudrun-wxcomponent)
- 职责：
  - 收 ticket、管 `component_access_token` / `authorizer_refresh_token`
  - 商户扫码授权、授权账号库
  - 代上传 / 审核 / 发布
  - 对内提供：`GET /inner/authorizer-access-token?appid=`

## 2. 微信授权与 Token 同步（方案 3 + 方案 A）

### 2.1 同步方式：方案 3

- CRMEB **不存** `authorizer_refresh_token`
- 运行时向 wxcomponent 要 `authorizer_access_token`
- CRMEB 只存 **`tenant_id ↔ authorizer_appid`** 及展示用元数据

### 2.2 绑定方式：方案 A（人工）

- 商户在微管家完成授权
- 平台端切换到该租户后，**人工选择 / 填写 appid 完成绑定**
- **不要求** wxcomponent 回调 URL 带 `tenant_id`（原版也不支持 per-tenant 回调）

### 2.3 职责切分

```text
wxcomponent（开放平台中枢）
  ├─ ticket / component token / refresh_token
  ├─ 商户扫码授权、授权账号库
  ├─ 代上传 / 审核 / 发布
  └─ 对外：/inner/authorizer-access-token?appid=

CRMEB（SaaS 商城）
  ├─ tenant + 业务隔离
  ├─ tenant ↔ appid（人工绑定）
  ├─ 运行时要 token → 调 wxcomponent
  └─ 支付服务商 / 分账 / 订单业务
```

### 2.4 CRMEB 侧最小微信相关改造

1. 表：`tenant_wechat_authorizer`（`tenant_id`, `authorizer_appid`, `app_type`, `nickname`, `status`…）
2. 平台端：人工绑 / 解绑 UI（可外链微管家授权页）
3. `WechatTokenClient` → 调 `/inner/authorizer-access-token`
4. `MiniProgramService` / `WechatService` 取 token 改走 authorizer 路径
5. C 端：`appid → tenant_id` 中间件解析

## 3. 平台端架构

### 3.1 入口与登录

| | 平台端 | 租户端（现有后台改造） |
|--|--------|------------------------|
| 入口 | **同域二级路径** `/platform`（不独立域名） | 现有后台路径（如 `/admin`） |
| 用户表 | `platform_admin`（新建） | `system_admin`（带 `tenant_id`） |
| Token | 平台 JWT，默认无业务 `tenant_id` | 租户 JWT，强制 `tenant_id` |
| 前端 | 建议新建 `template/platform`，构建到 `public/platform` | 现有 `template/admin` |
| 后端 | 建议新建 `platformapi` | 现有 `adminapi` |

部署示例（同一站点域名）：

```text
https://shop.example.com/platform          → 平台前端
https://shop.example.com/platformapi/...  → 平台 API
https://shop.example.com/admin             → 租户后台
https://shop.example.com/adminapi/...      → 租户 API（现有）
```

**禁止**：用现有超管直接当平台账号；平台与租户登录态不得混用（即便同域，Cookie / Token 存储键也要分开）。

### 3.2 「切换商户」与「进入租户」

- **切换商户**：平台端选定 `tenant_id` 后，配置该租户的应用 / 支付 / 装修等（仍在平台 UI）
- **进入租户**：签发短时运维票据 → 同域跳转租户后台（如 `/admin`）→ 兑成带标的租户 JWT，复用商品订单等页面

### 3.3 建议后端骨架

```text
crmeb/app/platformapi/
  controller/Login.php
  controller/Tenant.php
  controller/TenantWechat.php
  middleware/PlatformAuthTokenMiddleware.php
  route/...
```

API 前缀示例：`/platformapi/`

## 4. 模块归属总表（定稿）

图例：

- **平台·全局**：不随商户切换变化
- **平台·切商户**：平台端选定租户后配置
- **租户端**：商户后台
- **外置**：wxcomponent
- **砍掉**：不做

### 4.1 平台 · 全局

| 模块 | 说明 |
|------|------|
| 系统配置（非店招） | 地图 Key、WAF、远程登录等 |
| 维护（整模块） | 清缓存、日志、文件校验/管理、清数据、备份、定时任务、升级、商业授权等 |
| 城市数据 | **全站一份** |
| 接口：系统存储 | 统一桶 + 对象键带 `tenant_id` 前缀 |
| 接口：物流查询、采集商品等 | 平台共用 API Key |
| 支付：服务商主体 | `sp_mchid` / `sp_appid`、平台支付证书等 |
| 支付：分账接收方 | 平台抽成商户号 / 全称 |
| 研发元数据 | 代码生成、配置分类/列表、数据字典、CRUD、接口管理、自定义事件等 |
| 租户生命周期 | 开户、启停、到期、套餐 / 配额（新建） |
| 平台管理员 | `platform_admin` |
| **跨租户报表** | 平台数据看板 / 监管统计 |

### 4.2 平台 · 切商户

| 模块 | 说明 |
|------|------|
| **应用（整模块）** | 公众号 / 小程序 / PC / APP **配置** + **运营**（菜单、图文、回复、小程序链接等） |
| 店招 | 站点名称、LOGO、分享文案（从原「系统配置」拆出） |
| 支付（商户侧） | 子商户号 `sub_mchid`、该租户支付相关项 |
| 短信接口 | 按租户通道账号 |
| 一号通账户 | 按租户 |
| 短信购买 / 短信模板相关 | 按租户 |
| 电子发票 | 按租户 |
| 电子面单 | 按租户 |
| **装修** | 主题风格、微页面、店铺 DIY、组合数据类首页配置等 |
| **附件管理** | 与租户端共用数据，按租户隔离；平台切商户后也可管理 |
| 微信绑定 | `tenant_id ↔ authorizer_appid` 人工绑定；外链微管家授权 |

> 应用内「上传 / 发布」与 wxcomponent 重叠：平台页建议 **入口跳转微管家**，避免双轨维护。

### 4.3 租户端

| 模块 | 说明 |
|------|------|
| 首页 / 工作台 | 本租户数据 |
| 商品 | 分类、规格、评论、保障等 |
| 订单 | 订单 / 售后 / 发票 / 收银等 |
| 用户 | 用户、等级、标签、会员卡等 |
| 营销 | 拼团、券、秒杀、砍价、积分商城、预售、抽奖、签到、新人礼等 |
| 财务 | 账单、流水、提现、充值、佣金、余额记录等 |
| CMS 文章 | 文章与分类 |
| **分销** | 分销员管理 / 申请（一级菜单名「分销」） |
| **分销配置 / 分销等级** | 含平级奖等经营规则（在设置下） |
| **客服全套** | 客服配置、客服管理、话术、留言、自动回复 |
| 消息管理 | 通知开关与模板内容 |
| 协议管理 | 用户协议、隐私等 |
| 小票配置 | 打印小票 |
| 管理权限 | 管理员、角色、权限规则（租户范围） |
| 发货设置 | 物流公司、运费模板、门店 / 提货点 / 核销员 / 配送员等 |
| **附件管理** | 与平台切商户入口共享，按租户隔离 |

### 4.4 外置 / 砍掉

| 项 | 归属 |
|----|------|
| 开放平台 ticket / token / 授权 / 代发布 | **wxcomponent** |

## 6. 数据与隔离要点

### 6.1 租户识别

| 端 | 方式 |
|----|------|
| C 端小程序 / 公众号 | `appid` → `tenant_wechat_authorizer` → `tenant_id` |
| 租户后台 | 登录账号所属 `tenant_id` |
| 平台切商户 | 显式选择 `tenant_id` 写入平台操作上下文 |
| 平台进入租户 | 短时 ticket 兑租户运维 JWT |

### 6.2 强制隔离

- 业务表加 `tenant_id`；Model / 全局 Scope 默认过滤
- 写入自动填充 `tenant_id`
- 附件、配置（按租户项）、装修数据均按租户隔离
- 城市数据、全局系统配置、全局接口 Key **无** `tenant_id` 或独立平台表

### 6.3 建议新建 / 核心表（草案）

```text
platform_admin
tenant                          # code, name, status, expire_at…
tenant_wechat_authorizer        # tenant_id, authorizer_appid, app_type, status…
# package / tenant_package      # 可二期
# 业务表普遍增加 tenant_id
```

## 7. 与现有能力的关系

| 现有能力 | SaaS 中的位置 |
|----------|----------------|
| 单店分账（`ProfitSharingServices` 等） | 演进为平台抽成全局配置 + 租户子商户支付 |
| `mer_type` 微信支付服务商 | 支付侧服务商；**不是**开放平台第三方 |
| `Open3rd/` | 不作为授权中心；运行时改调 wxcomponent |
| 平级奖分销 | 留在租户「分销配置」内 |
| `wxcomponent/` | 已纳入仓库，独立部署到微信云托管 |

## 8. 建议实施顺序

详细可勾选拆解见：**[saas多租户改造实施清单.md](./saas多租户改造实施清单.md)**。

1. **基建**：`tenant` / `platform_admin` / `tenant_wechat_authorizer`；`platformapi` 登录；切商户上下文  
2. **平台壳**：租户 CRUD、人工绑 appid、进入租户兑票  
3. **Token 适配**：`WechatTokenClient` + 替换小程序/公众号取 token  
4. **配置迁移**：按本文菜单把应用 / 装修 / 接口按租户项迁到平台切商户；全局项迁平台全局  
5. **租户隔离**：业务主链路 Scope；附件隔离；去掉事业部  
6. **跨租户报表**  
7. **联调**：多小程序、支付子商户、分账、串数据审计
