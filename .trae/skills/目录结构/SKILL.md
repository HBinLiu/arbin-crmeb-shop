# CRMEB 项目代码结构分析

## 0. 自动触发说明

### 0.1 触发条件

#### 0.1.1 操作触发
- **文件浏览时**: 当浏览项目目录结构时自动调用
  - 打开项目根目录时触发
  - 打开核心目录时触发
  - 浏览文件树时触发
- **文件操作时**: 当对文件进行操作时自动调用
  - 创建新文件时触发
  - 移动文件时触发
  - 删除文件时触发
- **目录操作时**: 当对目录进行操作时自动调用
  - 创建新目录时触发
  - 重命名目录时触发
  - 删除目录时触发

#### 0.1.2 内容触发
- **关键词触发**: 当文件内容包含以下关键词时自动调用
  - 结构关键词: `目录`、`结构`、`架构`、`组织`、`层次`
  - 模块关键词: `模块`、`组件`、`服务`、`控制器`、`模型`
  - 路径关键词: `路径`、`位置`、`存放`、`位于`、`所在`
- **代码触发**: 当查看特定类型代码时自动调用
  - 控制器代码 (`Controller`)
  - 模型代码 (`Model`)
  - 服务代码 (`Service`)
  - 配置代码 (`Config`)

#### 0.1.3 命令触发
- **终端命令触发**: 当执行以下命令时自动调用
  - `ls`/`ls -la` (查看目录)
  - `find` (查找文件)
  - `tree` (查看文件树)
  - `du` (查看目录大小)

### 0.2 适用场景

#### 0.2.1 核心场景
- **项目探索**: 新成员了解项目结构时
- **代码导航**: 查找特定文件或模块时
- **架构分析**: 分析项目架构设计时
- **重构规划**: 规划代码重构时

#### 0.2.2 辅助场景
- **文件定位**: 快速定位文件位置时
- **模块了解**: 了解特定模块功能时
- **依赖分析**: 分析模块间依赖关系时
- **性能优化**: 分析代码结构以优化性能时

### 0.3 触发机制

#### 0.3.1 调用时机
- **实时触发**: 目录操作时立即触发
- **延迟触发**: 复杂文件操作时延迟1秒触发
- **批量触发**: 批量文件操作时合并触发

#### 0.3.2 调用频率
- 目录浏览: 最多每10秒触发一次
- 文件操作: 最多每5秒触发一次
- 命令执行: 最多每3秒触发一次

#### 0.3.3 调用优先级
- **优先级等级**: 高优先级 (4/5)
- **竞争处理**: 当多个技能同时触发时
  - 最高优先级: 系统核心技能
  - 高优先级: 代码结构技能
  - 中等优先级: 文档规范技能
  - 低优先级: 辅助工具技能
- **触发限制**: 仅在代码相关操作时被触发，不影响其他技能的正常使用

### 1.2 核心目录详解

#### 1.2.1 app 目录
- **api/**：RESTful API 接口实现，处理移动端和第三方请求
- **controller/**：MVC 控制器，处理 HTTP 请求和响应
- **dao/**：数据访问对象，封装数据库操作，提供数据访问方法
- **model/**：数据模型，定义数据库表结构和关系
- **services/**：业务逻辑服务，实现核心业务功能
- **event/**：事件处理器，响应系统事件
- **middleware/**：中间件，处理请求前的验证和处理
- **validate/**：数据验证器，验证用户输入数据

#### 1.2.2 config 目录
- **app.php**：应用主配置
- **database.php**：数据库配置
- **route.php**：路由配置
- **cache.php**：缓存配置
- **queue.php**：队列配置

#### 1.2.3 crmeb 目录
- **basic/**：基础类库，提供通用工具和基类
- **exception/**：异常处理类，定义系统异常
- **services/**：核心服务，提供系统级功能

#### 1.2.4 public 目录
- **admin/**：后台管理系统前端代码
- **api/**：API 接口文档和测试工具
- **mobile/**：移动端前端代码
- **static/**：静态资源文件 (CSS/JS/图片)

## 2. 核心模块

### 2.1 控制器模块 (`app/controller/`)
- **功能**：处理 HTTP 请求，路由分发，响应客户端
- **特点**：RESTful 风格，分层清晰，参数验证
- **关键文件**：`BaseController.php` (控制器基类)

### 2.2 服务模块 (`app/services/`)
- **功能**：实现核心业务逻辑，封装业务规则
- **特点**：业务逻辑集中，可复用性高，易于测试
- **关键文件**：各业务服务类

### 2.3 数据访问模块 (`app/dao/`)
- **功能**：封装数据库操作，提供数据访问方法
- **特点**：SQL 集中管理，防止 SQL 注入，提高安全性
- **关键文件**：各数据访问对象类

### 2.4 模型模块 (`app/model/`)
- **功能**：定义数据模型，处理数据关系
- **特点**：ORM 映射，自动表结构，关联查询
- **关键文件**：`BaseModel.php` (模型基类)

### 2.5 核心库模块 (`crmeb/`)
- **功能**：提供基础类和工具方法
- **特点**：通用性强，系统级支持
- **关键文件**：基础工具类和服务类

## 6. 架构特点

### 6.1 分层架构
- **表现层**：controller/api - 处理请求和响应

- **数据层**：dao/model - 数据访问和模型
- **基础层**：crmeb/basic - 基础类和工具

### 6.2 设计模式
- **MVC**：模型-视图-控制器模式
- **RESTful**：API 设计风格
- **依赖注入**：服务容器和依赖管理
- **事件驱动**：事件系统和观察者模式

### 6.3 技术特点
- **模块化**：功能模块化，易于扩展
- **可测试**：分层设计，易于单元测试
- **高性能**：缓存机制和数据库优化

## 8. 最佳实践

### 8.1 代码组织
- 遵循分层架构，不要跨层调用
- 控制器只负责请求处理，业务逻辑放在服务层
- 数据库操作封装在 DAO 层，模型只定义结构

### 8.2 目录管理
- 按照功能模块组织目录结构
- 保持目录层次清晰，避免过深嵌套
- 使用语义化的目录和文件命名

### 8.3 性能优化
- 合理使用缓存，减少数据库查询
- 避免复杂的 SQL 关联查询
- 使用队列处理耗时操作
- 优化文件和目录结构，提高加载速度
